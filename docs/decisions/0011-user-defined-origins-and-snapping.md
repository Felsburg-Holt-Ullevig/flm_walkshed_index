# 0011. User-defined origins and initial snapping rules

Status: Accepted initial product rules; implementation pending
Date: 2026-11-09

## Decision

Users choose custom origins by map click or latitude/longitude entry. Points may represent stations, stops or other locations. Verified station entrances are not a prerequisite for analysis of a user-defined point.

Connect each point to the nearest walkable network location within **500 international feet**, inclusive. Search eligible pedestrian segments and their nodes; the closest position may lie partway along a segment or at a node. Excluded or unresolved segments are not eligible merely because they are nearer. Preserve existing source connectivity and permitted walking directions when starting traversal.

Measure proximity by straight-line distance from the entered point to the candidate network location. Prefer the smallest straight-line distance when choosing among candidates. No connecting distance or time is deducted from the walking budget; the full budget begins at the selected network location.

If no eligible network location is within 500 feet, reject walkshed analysis for that point and flag the rejection with a clear reason. Do not present an empty successful walkshed or a zero result. Other valid points can still be analyzed. Ordinary successful snaps require no user-facing snap flag or warning.

## Boundaries and remaining detail

These rules authorize a geometric connection; they do not test whether the short connection crosses a fence, river or railway. No barrier-aware connector or user confirmation step is required by this decision. Internal origin, selected segment/node, offset and distance should remain available for reproducibility without requiring a user-facing snap flag.

Straight-line distance resolves candidates at different distances. For exactly equal distances, select the northernmost candidate segment: compare the latitude of each candidate's closest snap point and prefer the greater latitude. This arbitrary directional preference is accepted for the initial product. If distance and snap-point latitude are both equal, use stable source candidate ID ordering as a final engineering fallback so input order cannot change the result. Numerical distance tolerance and geographic distance computation must also be specified and tested without changing the 500-foot product limit.

The earlier 100-foot, charged-access and ambiguous-origin experimental references remain historical test evidence. This decision defines future user-defined origin behavior; it does not change their accepted bytes or claim that the current browser harness already supports coordinate origins. No source data, prior run output or expected result is regenerated by documenting this decision.
